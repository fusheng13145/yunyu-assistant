# 项目规格（PROJECT-SPEC）

> 定位 / 目标 / 范围。本文写"要做什么、不做什么、怎么算做成了"。
> 已实现能力的逐条说明在[手册第 1–2 章](云谕助手项目手册.md#第-1-章-项目概述)，本文不重复。

## 1. 一句话定位

**面向开发与运营人员的"AI 语音助手搭建 + 模型调试"一体化 Web 平台**：像配置 ChatGPT 一样配置一个能打电话、
带人设、接私有知识库的 AI 助手，并能在网页上边聊边看中间过程（ASR 转写、LLM 流式、工具调用、知识命中）。

差异化不在模型能力（模型能力可采购），而在**治理与私有化**：数据归属隔离、用量配额、全程审计、可自带 Key 与自带知识库。
这条判断的完整论证与横向对比见[手册 6.7](云谕助手项目手册.md#67-与豆包能力横向对比与差距收口路线)。

## 2. 目标用户

| 画像 | 诉求 | 本产品对应能力 |
|---|---|---|
| 个人开发者 / 极客 | 5 分钟建助手，浏览器里直接打电话体验 | 助手配置 + 语音工作台 |
| 产品 / 运营 | 可视化改人设与话术，回看对话与通话 | 人设编辑与持久化、记录与详情、对话导出 |
| 企业内部团队 | 私有知识检索、数据隔离、用量与审计 | RAGFlow 知识库、组织角色矩阵、配额账单、审计日志 |
| 第三方集成方 | 用 API 把助手接进自己的系统 | 开放 OpenAPI（文本 SSE / 语音握手 / PSTN 外呼 / Webhook） |

## 3. 交付标准（本产品与"demo"的区别所在）

**不是每个计划功能都要有，但已实现的每个功能都必须站得住。**

由此推出四条硬口径：

1. **能力要么生效，要么不存在。** 字段存在但不参与判定（如早期的 `scopes`）、配置项存在但注不进来（如早期的 Webhook 重试）、
   端点存在但没人调用（如 v2.53 删掉的 `/api/knowledges` 一组），都按缺陷处理：要么修好，要么删掉，要么显式登记为"未生效"。
2. **失败必须说出来。** 静默降级（检索失败长得像"知识库没答案"、上传失败只进 `console.error`、拒绝回执没人消费）
   是本项目最主要的缺陷来源，历次批次有一半在收这类问题。
3. **宣称要能被反证。** 文档说它在做的事，代码得真的在做；每条"已验证"要写清验证层级（单测 / 真机冒烟 / 浏览器级），
   没跑过的不许写成跑过。
4. **允许"只登记不修"，但不允许顺手改行为。** 读码发现的缺陷可以进候选清单（手册 7.4）等排期，但不能在同批次里
   被"顺手"改掉——那会让批次边界失效。

## 4. 范围：第一阶段（上线目标）

第一阶段的成功判据是一个**能在公网被小范围真实用户使用的实例**，而不是功能数量。已在手册 6.7 拍板的三项决策：

| 决策 | 内容 | 影响 |
|---|---|---|
| 部署位置 | 国内云 + ICP 备案 | 需要常驻 JVM + 反向代理 + 域名备案周期；不是 Serverless/边缘平台 |
| 注册准入 | 常规账密注册即为产品形态，邀请码退为**可选运营手段**（v2.89 把原"两阶段"收敛为同一份代码的两个档位） | `REGISTRATION_MODE` 默认 `open`；判定仍只认显式 `open`，写错值按 `invite` 处理（要收回闸门不必发版）。显式 `invite` 时第一个管理员仍有"注册要码、发码要管理员"引导死锁，解法见手册 5.10④ |
| 语音能力 | **不进第一阶段** | 语音主链路可继续存在于产品里，但不作为公网首发的验收项（缺真实网关联调） |

第一阶段范围内的收口工作（已完成的部分见手册 7.5）：凭据与配置安全、来源地址与限流、审计可信度、
开放平台能力与凭据、吞错显性化、备份与恢复演练、部署清单与验收脚本。

## 5. 范围：明确不做 / 后置

| 项 | 状态 | 原因 |
|---|---|---|
| 官网 / 营销页 | 不做 | 本产品是登录后的工作台，无公开落地页；视觉规范只服务于应用本身（见 [DESIGN.md](../DESIGN.md)） |
| 组件库对外分发 | 不做 | 前端只有 4 个共享组件，全部服务本仓视图；`docs/REGISTRY.md` 登记的是仓库内真实的六张"登记表"，不是包分发说明 |
| Cloudflare / Vercel 式托管 | 不适用 | 需要常驻 JVM、WebSocket 长连接、MySQL、定时任务；部署说明见 [DEPLOYMENT.md](DEPLOYMENT.md) |
| 语音二期（coturn 部署） | 后置 | 混音已于 v2.87 交付、通话中时长与墙钟已于 v2.59/v2.86 收口、TURN 凭据签发与轮换已于 v2.88 收口；剩下的只有 coturn 服务器部署与真机穿透验收（人工/外部），见 [TODO.md](../TODO.md) 第四节 |
| Spring Security / 权限模型改造 | 不做 | 现有自研拦截器 + 业务层归属校验是一致且可测的；换成框架属重构而非收口 |
| 独立状态库（Pinia）/ HTTP 客户端（axios） | 已下线 / 不引入 | 登录态与消息流的现有形态已被门禁覆盖；加依赖需单独批准 |
| 计费与支付 | 不做 | 只做到"配额 + 账单视图"，不接支付通道 |
| 多区域 / 高可用 | 不做 | Redis 已可支撑多实例共享状态，但不为可用性目标做架构 |
| 组织共享知识库 | **不做（2026-10-03 拍板：纯个人用）** | `knowledgebases.org_id` 无写入路径、组织三条读分支走不到是**选定形态**而非缺陷（原候选 ㊵ 就此关闭）；扩展为团队产品时再立写入路径与成员角色校验，见下"未来规划" |
| 多实例部署 | **不做（2026-10-03 拍板：单实例）** | 拒绝台账进程内计数（㉟）、语音能力吊销回合级窗口（㊲）等"多实例才成立"的候选**维持登记不修**；见下"未来规划" |

## 5.5 未来规划（已拍板的"现在不做、扩展时再做"，2026-10-03）

以下事项由用户明确裁决"放到现在不做、留待扩展"，不是遗忘也不是缺陷：

1. **组织协作深化**（组织共享知识库、组织级配额视图）：前提是产品从纯个人用扩展为团队/企业形态；届时先改手册 4.5 第 13 条的归属例外申请，再立 `knowledgebases.org_id` 写入路径与成员角色校验。
2. **多实例部署**：拒绝台账落库/Redis 聚合（㉟）、语音能力吊销跨实例失效机制（㊲）、录音目录共享卷口径，届时一并设计。
3. **语音二期**（已立项推进，见 TODO.md 第四节）：WebAudio 混音由 v2.87 交付，TURN 凭据签发与轮换由 v2.88 交付；**代码侧已无剩余项**，端到端验收依赖真实 RustPBX 网关、ASR/TTS 账号与 coturn 部署（人工/外部）。

## 6. 关键约束（影响方案的既有事实）

- **第三方依赖全部可缺省**：未配置的服务商（RAGFlow / 搜索 / 天气 / 图像 / 视频 / 网关）要么功能运行时降级，
  要么工具根本不注册给模型；只有 LLM Key 与库凭据是启动硬依赖。降级矩阵见手册 6.3。
- **语音 ASR/TTS 由 RustPBX 网关侧代理**，本应用不持有腾讯云凭据 ⇒ 网关侧参数（音色、打断、静音超时）是运维配置项。
- **数据规模假设是"小规模真实使用"**：归档与容量治理已有（手册 6.4），但不按大数据量设计分库分表。
- **验证手段有天花板**：自 v2.75 起本仓有浏览器级 E2E 守卫（`frontend/e2e`，Playwright，需真实后端与登录账号、刻意不进 CI），观感与真实渲染不再只有"纯函数 + Node 桩测 + 构建期类型检查"这一条间接通道；
  但它覆盖不到需要外部设备的链路（真网关通话、真实音频回放），这类改动仍须在口径里写明未验证。跑法见 [DEVELOPMENT.md](DEVELOPMENT.md) §7.3。
