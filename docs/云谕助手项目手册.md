## 第 1 章 项目概述

### 1.1 项目定位

> **面向开发与运营人员的"AI 语音助手搭建 + 模型调试"一体化 Web 平台。**

一句话概括：**"配置即用、边聊边调、语音与文本双通道、知识可控、全程可审计。"**

- **形态**：浏览器即用（通话依赖 WebRTC，无需安装客户端）。
- **业务本质**：像配置 ChatGPT 一样配置一个能打电话、带人设、接私有知识库的 AI 语音助手，并能在网页上边聊天边调试（实时看 ASR 识别、LLM 流式输出、工具调用、知识命中）。
- **重构范围**：Java + Vue 全栈实现，替换早期 Go 参考版。

### 1.2 目标用户与价值

| 用户画像 | 核心诉求 |
|---|---|
| 个人开发者 / 极客 | 5 分钟建助手，直接在浏览器打电话体验 |
| 产品 / 运营人员 | 可视化编辑人设与话术、查看对话与通话记录 |
| 企业内部团队 | 私有知识检索、数据归属隔离、用量统计、操作审计 |

### 1.3 核心能力清单

| 模块 | 能力 |
|---|---|
| 用户认证 | 注册/登录/登出/修改密码/个人资料；JWT 无状态鉴权；登录限流 |
| 助手管理 | 助手 CRUD（软删除）、属主权限校验、人设/音色/模型参数配置、知识库绑定、人设模板 |
| 语音通话 | WebRTC 建链、ASR 实时转写、LLM 流式回复、TTS 播报、VAD 打断、沉默追问、LLM 主动挂断、通话记录 |
| 文本对话 | 流式对话、人设热更新、知识库动态切换、对话重置、工具调用可视化、Markdown 渲染 |
| 知识库 | RAGFlow 双层后端代理（密钥零下发）、文档上传/删除/切片解析、多库联合检索、检索效果测试 |
| 记录统计 | 通话记录列表/详情、按日周月用量统计 |
| 组织协作 | 组织/团队成员管理（owner/editor/viewer）、组织内资源共享与角色隔离 |
| 用量配额 | 助手上限、单日通话/时长/消息量配额拦截 + 用量账单视图（组织优先/用户兜底） |
| 开放 API | 第三方应用 API Key、文本对话 SSE（`/api/open/chat`），用量计入属主配额 |
| 辅助 | 音色字典、模型字典、快捷命令、对话导出、消息搜索 |
| 工程 | 操作审计、健康检查、全局异常与脱敏、环境变量化配置 |

## 第 2 章 核心功能说明

### 2.1 账号认证（Auth）

后端入口：[AuthController.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/controller/AuthController.java)

| 功能 | 说明 |
|---|---|
| 注册 | `POST /api/auth/register`；用户名全局唯一；密码 BCrypt 加密存储 |
| 登录 | `POST /api/auth/login`；签发 JWT；同一错误文案"用户名或密码错误" |
| 个人信息 | `GET /api/auth/me`；返回时密码置空 |
| 修改密码 | `PUT /api/auth/password`；校验原密码 + 新密码复杂度；成功后旧 Token 仍有效（无主动失效机制） |

**规则要点：**
- 密码复杂度：**至少包含一个字母和一个数字，长度 ≥6 且 ≤128**（注册与改密一致，正则 `PASSWORD_PATTERN_RELAXED`）。
- 用户名长度 ≤32；密码 ≤128。
- 登录/注册接口由 `RateLimitInterceptor` 限流（同一 IP 1 分钟内最多 5 次，滑动窗口，超限返回 429 + `Retry-After`）。
- 登录操作写入审计日志（`@Audit(action="LOGIN")`）。

> ⚠️ **已知限制**：当前为**单一短时 JWT**（无 refresh/登出黑名单）；AccessToken 逻辑上由 `AuthInterceptor` 校验有效性。

### 2.2 助手管理（Assistant）

后端入口：[AssistantController.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/controller/AssistantController.java)

| 功能 | 方法/路径 | 说明 |
|---|---|---|
| 创建 | `POST /api/assistants` | 归属当前用户，创建时写入 userId |
| 列表 | `GET /api/assistants` | 仅返回当前用户助手，按创建时间倒序 |

**助手字段**：`name / description / personality(人设) / voice(音色) / modelName / temperature(0-2) / maxTokens / knowledgeIds(JSON 数组，对外为数组，DB 存字符串)`。

### 2.3 语音通话对话（Voice）

后端入口：[VoiceController.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/controller/VoiceController.java)、[VoiceSignalingHandler.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/handler/VoiceSignalingHandler.java)、[RustPBXService.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/service/RustPBXService.java)

**通话链路**：

```
浏览器 getUserMedia → RTCPeerConnection.createOffer
        │  WS(/ws-voice/{assistantId}) offer{sdp}
        ▼
VoiceSignalingHandler → RustPBXService.connectToRustPBX（Invite + callOption）
        ▼
RustPBX 返回 answer SDP → webrtc_answer 回传前端
        ▼
webrtc_connected → 播放问候语 → 创建通话记录(进行中) 并下发 callId
        ▼（语音上行）
ASR 回调 → asr_delta 实时上屏 → ChatService.chatStream → LLM 流式
        │  按段 → TTS 播报（sendTTS）＋ assistant_message 文本流
        ▼（结束）
query_end（携带 message / costTime / knowledgebase）→ 挂断 → 落库
```

**关键行为：**
- **会话 ID**：`RustPBXService` 内部使用 `UUID.randomUUID()` 作为网关会话 ID（每次呼叫唯一），避免并发串号。
- **沉默追问**：音轨结束后 `silence_timeout`（默认 30s）未说话即 TTS 播报"您还在吗？请说点什么吧!"。
- **VAD 打断**：`break_on_vad`（默认 true）由网关侧在用户开口时打断 TTS。
- **LLM 主动挂断**：模型调用 `hangup` 工具时触发 `handleLlmHangup` → 通知前端 + 释放资源 + 关闭会话。
- **通话记录**：`webrtc_connected` 时创建（status=进行中），挂断/会话关闭时结算时长与消息数（正常结束/中断）；`webrtc_connected` 消息携带 `callId` 供前端录音回传。
- **通话录音（v2.12）**：前端 `useWebRTC` 在收到 `callId` 后启动 `MediaRecorder`（本方麦克风 + 远端 AI 音轨合成，`audio/webm;codecs=opus`），挂断时先取录音 blob 再清理连接，异步 `POST /api/call-records/{id}/recording` 上传；后端以 `{callId}.webm` 存入 `app.recording.dir`（`RECORDING_DIR`）并回写 `call_records.recording_name`；通话记录详情/列表带 `recording` 标志，前端可 `GET /api/call-records/{id}/recording` 拉流回放。
- **弱网降级（v2.12）**：前端监听 `RTCPeerConnection.connectionState`，`failed` 时自动结束语音通话并提示改用文字对话。
- 支持 8 个音色（4 女 4 男，腾讯 TTS 代码）。

> ⚠️ 通话依赖 WebRTC 的 STUN 穿越；**生产建议配置 TURN 服务器**以穿透对称 NAT（见 6.6）。

### 2.4 文本对话与模型调试（Chat）

后端入口：[ChatWebSocketHandler.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/handler/ChatWebSocketHandler.java)、[ChatService.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/service/ChatService.java)

- `WS /ws/{assistantId}` 建立会话：校验助手归属 → 加载人设与历史（最近 50 条）→ 推送 `assistant_info`。
- `chat{content}` 触发流式回复；`assistant_message{segment}` 分段下发，`query_end` 携带 `message / costTime / knowledgebase / tokenUsage`。
- `prompt{content}` 实时热更新人设（清空历史）。
- `selectedKbIds{ids}` 动态切换检索知识库。
- `resetMessage` 重置上下文。
- **工具调用上限**：单轮最多 5 次工具递归，防无限循环。
- **对话历史截断**：注入 LLM 的上下文最多保留最近 60 条消息；落库记录完整。
- **知识库注入**：检索结果以"参考信息"追加到系统提示词；命中信息随 `query_end.knowledgebase` 返回（docCount/docName）。

### 2.5 知识库管理（Knowledge + RAGFlow）

后端入口：[KnowledgeBaseController.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/controller/KnowledgeBaseController.java)、[RagflowProxyController.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/controller/RagflowProxyController.java)、[KnowledgeService.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/service/KnowledgeService.java)

**设计要点：**
- **双层后端代理**：前端一律经 `/api/ragflow/*` 转发到 RAGFlow，**API Key 永不下发前端**。
- 本地 `knowledgebases` 表记录数据集元数据（含 `dataset_id` 关联与 `user_id` 归属）。
- **对象级授权**：数据集文档接口（列表/上传/删除/切片）均校验 `isOwnedDataset(datasetId, userId)`，非本人数据集返回 403。

后端入口：[OpenApiAuthInterceptor.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/interceptor/OpenApiAuthInterceptor.java)、[OpenApiChatController.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/controller/OpenApiChatController.java)、[ApiAppController.java](file:///c:/Users/ASUS/Desktop/实战项目/云谕助手/yunyu-assistant/backend/src/main/java/com/leyon/backend/controller/ApiAppController.java)

- **文本对话多轮会话（v2.15）**：`POST /api/open/chat`（body `{assistantId, message, sessionId?}`）对话流式输出为 `text/event-stream` SSE，复用 `ChatService`（属主校验 + 组织分支 + 配额 `checkSendMessage` 计入属主身份）；**首轮不传 `sessionId` 自动创建会话**，携带 `sessionId` 续聊（校验归属与助手匹配后加载历史注入上下文）；对话结束后落库 `records`（按 session 归集）并自动生成标题，**结束帧（`streamEnd:true`）回传 `sessionId`** 供第三方下一轮接力。
- **语音会话（v2.16）**：`WS /api/open/ws-voice/{assistantId}` 开放 WebRTC 语音会话（信令协议与 `/ws-voice/{assistantId}` 完全一致：offer/webrtc_answer/webrtc_connected{callId}/asr_delta/assistant_message/query_end/hangup），复用 `VoiceSignalingHandler` 全链路（ASR/TTS/通话记录/配额/组织归属）；**鉴权方式**：浏览器 WebSocket 无法设自定义头，须用 URL 查询参数 `?apiKey=xxx`；非浏览器客户端（curl/mobile/server）可附 `X-API-Key` 请求头；握手未携带/无效/停用 Key 均 401 拒绝；跨域放行任意第三方 Origin（`setAllowedOriginPatterns("*")`，安全依赖 app_key 保密，建议第三方在可信域部署）。
- **绑定** Webhook 应用（P2-17）：创建应用时可指定 `webhookUrl`；`webhook_secret` 于创建时生成（v2.19 补，v2.17 遗漏致签名恒不生效），用于 HMAC-SHA256 签名，**仅创建响应一次性展示**（不随列表返回）。
- **PSTN 外呼（P2-17/v2.18）**：`POST /api/open/call`（body `{assistantId, phoneNumber}`）完成参数校验、助手归属（org 分支）与 `QuotaService.checkStartCall` 配额拦截后创建**外呼任务**（`outbound_calls` 表，返回 `{taskId, status:"PENDING"}`）并异步经可插拔 `PstnGateway`（默认 `HttpPstnGateway`：POST JSON 到 `app.pstn.gateway-url`；未配置网关时任务置 FAILED「PSTN 网关未配置」）发起；状态机 PENDING→DIALING→ACTIVE→COMPLETED/FAILED；网关后续状态经 `POST /api/open/callbacks/pstn` 回调（请求头 `X-Gateway-Token` == `app.pstn.callback-token` 校验，防伪造；已从 OpenApiAuthInterceptor 排除）；**DIALING 超时自动扫描（v2.18）**：`OutboundCallTimeoutScheduler` 按 `app.pstn.scan-interval-ms` 周期扫描 `DIALING` 滞留超过 `app.pstn.timeout-ms`（默认 120s）的任务置 FAILED「呼叫超时未接通」并投递 `call.status_changed` Webhook。
- **Webhook 回调（P2-17）**：应用配置 `webhookUrl` 后，事件异步投递（线程池）+ 失败重试（指数退避，默认最多 3 次）+ 投递记录落库 `webhook_deliveries`；请求头携带 `X-Webhook-Signature: HMAC-SHA256(webhook_secret, body)`（secret 为空不签名）。支持事件：

| 事件 | 触发点 | payload 关键字段 |
|---|---|---|
| `call.connected` | OpenAPI 语音会话接通（createCallRecord） | callId/assistantId/userId |
| `call.completed` | OpenAPI 语音会话结束（finishCallRecord） | callId/status/durationSec/messageCount/recording |
| `call.status_changed` | PSTN 外呼创建与网关回调 | taskId/status/failReason |
| `message.completed` | OpenAPI 文本对话流结束（落库后） | assistantId/message/sessionId |

- **边界**：Webhook 重试为定时扫描制（`app.webhook.retry-interval-ms`）；PSTN 外呼 `ACTIVE` 后**媒体回流不实现**（无 PSTN↔浏览器双向通话，因 RustPBX 网关无 SIP↔WebRTC 媒体中继能力；网关升级支持后可在 `PstnGateway` 协议回传媒体端点实现对讲，不改任务状态机）。

- **鉴权**：
  - REST：`AuthInterceptor`（`/api/**` 除 `/api/auth/**` 与 `/api/open/**`）；
  - OpenAPI：`OpenApiAuthInterceptor`（`/api/open/**`，`X-API-Key` 鉴权，与 JWT 通道隔离）；
  - WS：`WebSocketAuthInterceptor` 握手校验 + 业务处理器首条 `auth` 双通道；
  - 限流：`RateLimitInterceptor`（`/api/auth/login`、`/api/auth/register`，IP 维度）。
- **数据权限**：业务层显式 `userId` 归属校验（助手/知识库/会话/通话记录），组织数据（`org_id` 非空）按 [2.10 组织与数据隔离](#210-组织与数据隔离p2-10) 角色矩阵共享——新增查询 API 时**必须**补 `userId`/`orgId` 条件。

## 第 4 章 开发规范

### 4.1 环境准备

| 项 | 要求 |
|---|---|
| JDK | 21 |
| Maven | 3.8+（仓库自带 `mvnw`/`mvnw.cmd`） |
| Node.js | ≥20 |

后端配置全部经环境变量注入，**禁止硬编码密钥/口令**（见 [5.3](#53-环境变量清单)）。

### 4.2 代码分层与职责

- **Controller**：请求参数校验（含归属校验）、调用 Service、返回 `ApiResponse`。
- **Service**：业务编排、事务、权限、（第三方隔离调用）。
- **Handler**：全局异常、WS 业务分发、MyBatis 自动填充。
- **拦截器**：鉴权/限流/WS 握手。
- **工具**：AI Function 工具，统一经 `ToolRegistry` 注册。

> 约束：Controller 不得写业务逻辑；领域间经 Service 调用，禁止跨层直连 Mapper。

### 4.3 命名与编码约定

- 包名/类名遵循 Java 约定；前后端保持一致命名。
- 数据库蛇形命名 → 实体驼峰（已开 `map-underscore-to-camel-case`）。
- 常量用 `static final` 并加注释；魔法值抽常量。
- 消息文案统一中文；错误提示由后端 `message` 下发，不做多余前端拼接。

### 4.4 异常与错误处理

- 业务异常抛出 `RuntimeException`/`IllegalArgumentException`，由 `GlobalExceptionHandler` 统一转为 `ApiResponse`。
- **禁止**透传异常原文给前端（已统一脱敏，见 4.5）。
- 第三方调用失败需捕获并降级（参考 [6.3 降级矩阵](#63-第三方依赖降级矩阵)）。

### 4.5 安全开发规范

1. **密钥管控**：所有 secret 走环境变量，前端零接触；禁止提交到版本库。
2. **越权防护**：任何按 id 查询/修改前，校验 `resource.userId == currentUser.id`。
3. **脱敏**：异常消息、日志中不得含密码/Token/Secret 明文。
4. **注入防护**：SQL 一律用 MyBatis-Plus 参数化 SQL，禁止字符串拼接用户输入。
5. **CORS**：白名单域名 + `allowCredentials`，禁止 `*`。
6. **上传**：限制大小 + 扩展名白名单。
7. **代理转发**：外部代理（如 `/api/ragflow`）须做归属校验与路径白名单，防止 SSRF/越权。

### 4.6 审计日志规范

- 对敏感/关键操作使用 `@Audit(action, targetType)`。
- 审计切面自动记录 userId/IP/targetId/结果，失败时携带 `failReason`。
- 新增审计类操作时，注意 `AuditAspect.findTargetId` 会取首个 ≤64 非空 String 参数，**建议将目标 ID 作为首个 String 参数**以保证采集准确；多 String 参数场景需复核。

### 4.7 前后端联调约定

- 所有接口返回 `ApiResponse`；前端统一在 `api/*` 解析 `code===200`，否则抛错。
- WS 消息类型集中在两端常量，新增消息须同步更新 [7.2](#72-websocket-消息参考)。
- 列表分页参数统一 `page/pageSize`，排序由后端决定。
- 前端不读取/不透传任何密钥。

### 4.8 测试与代码质量

- 后端现有测试仅冒烟测试 `BackendApplicationTests`；新增核心链路应补充单测。
- 前端建议配置 ESLint + 类型检查：`npx vue-tsc --noEmit`（`npm run type:check`）。
- 提交前执行：后端 `mvnw compile`、前端 `npm run build`。

## 第 6 章 维护指南

### 6.1 健康检查与监控

- 健康端点：`GET /actuator/health`（`show-details: always`）。
- 已暴露：`health / info / metrics`。

### 6.2 日志与排障

- 日志级别：根 `INFO`，`com.leyon.backend.mapper` 为 `DEBUG`（SQL 输出）。
- 关键链路均有 `logger` 埋点：WS 建连/认证、流式异常、语音网关连接、记录落库、审计失败。
- 定位思路：
  1. 先查 `/actuator/health` 与数据库连通性；
  2. 查 mapper DEBUG SQL 是否符合预期；
  3. 查第三方调用异常（RustPBX/RAGFlow/LLM）日志；
  4. 观察 `audit_logs` 与 `call_records` 状态。

### 6.3 第三方依赖降级矩阵

| 故障 | 降级行为 |
|---|---|
| LLM 不可用 | 流式结束推送错误文案，不静默 |
| 知识库检索失败 | 跳过检索，仅凭模型回答 |
| RustPBX / 语音网关故障 | 语音建链失败并提示；引导使用文本通道 |
| 搜索/天气工具失败 | 工具返回错误文案，LLM 兜底回答 |
| 上传解析失败 | 文件保留，提示手动解析 |

### 6.4 数据库运维

- **逻辑删除**：`is_deleted=1` 代表已删；查询默认过滤。
- **索引**：`records` 已含 `assistant_id`/`created_at`/`assistant_id+created_at`/`call_id`/`session_id` 索引，长会话分页查询按 `session_id + created_at` 走索引；量大后可续加复合索引。
- **归档策略（已落地 v2.13）**：`records`/`call_records`/`audit_logs` 超期数据（默认保留 180 天，`app.archive.*` 可配）经管理端 `POST /api/admin/archive/run` 或定时任务（`ARCHIVE_SCHEDULE_ENABLED=true` 开启）复制到 `*_archive` 归档表（保留原 id）后**物理删除**源表，`call_records` 关联的录音文件 (`RECORDING_DIR` 下 `{callId}.webm`) 一并清理；归档过程幂等（重跑安全），文件删除失败仅计数不影响数据一致性；`*_archive` 表仅保留 `created_at` 单列索引、不启用逻辑删除。
- **备份**：每日全量 + binlog 增量。
- **唯一索引注意**：`users.username` 为唯一索引，逻辑删除的用户名仍占用，同名无法重新注册（当前无注销功能，影响低）。

### 6.5 常见故障排查

| 现象 | 可能原因 | 建议 |
|---|---|---|
| 登录 429 | 限流触发 | 等待 `Retry-After`；检查代理 IP 透传 |
| 上传大文件失败 | 超过 Multipart 限制 | 已对齐 50MB，仍失败查反向代理 `client_max_body_size` |
| 语音通话建立失败 | RustPBX 不可用 / NAT 无 TURN | 检查网关连通、配置 TURN |
| 文本对话无回复 | LLM Key/模型失效 | 查后端日志第三方法调用 |
| 知识库检索无结果 | RAGFlow 未配置/数据集未归属 | 检查 `RAGFLOW_*` 与本地 `knowledgebases` 归属 |
| 403 无法访问数据集 | 归属校验拒绝 | 确认通过"创建知识库"在应用内创建（而非直连 RAGFlow 手工建集）|
